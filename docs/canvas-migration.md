# Roots & Routes into the Tree Canvas: the migration, one page

Written 18 Nov 2026 (phase 0). Read this before moving anything. It is the inventory and the rules; the phases say what moves when.

**Where things stand (19 Nov 2026).** At David's request ("remove orphans, tree canvas, import report, places to review and fix list from roots and routes") **five of Roots & Routes' six tabs were removed on 19 Nov 2026: Tree canvas, Orphans, Import report, Places to review and Fix list** (Export had gone earlier, #85). `/roots/` is now **Tree views only**: its tab strip is gone (a plain "Tree views" heading is left), its twelve views and everything they need (the header counts, "Open another file", "Kept on this device", "Hide living people", the MyHeritage and Ancestry links control, the stale-code warning) work as before. One quiet line at the top says "Fix list, Orphans, Places, the import report and export are now in the Tree Canvas" with an **Open the Tree Canvas** button (a link: the canvas has its own opening flow and keeps its own recent files, so the loaded file is not carried across). An old `/roots/#export` link, or any other hash, lands on Tree views with that line. **The Atlas menu's "Roots & Routes" entry now opens `/tree-canvas/`** (David: "yes, i want that"); the label is kept for now, and `/roots/` stays reachable from the canvas page ("Tree views (older page)" on its start page and on Your file). Everything the five tabs did is in the canvas: Your file (At a glance, What was read, Export), and the Fix list with its People, Places and Orphans tabs (#77, #79, #82, #88, #100). The modules the canvas imports from `/roots/js/` (worker, gedcom, checklist, decisions, orphans, placereview, metrics, report-view, myheritage, ancestry, remember, openlink, known-sites.json and the rest) stay where they are: they are the canvas's reader, not R&R's page.

**The aim.** The Tree Canvas (`/tree-canvas/`) becomes the one place a person opens a file, looks at their tree, understands what was read, fixes it and keeps their work. Roots & Routes (`/roots/`) is retired only when everything useful in it is better in the canvas, one piece at a time. Nobody is ever left without a working page in between.

## Principles (these decide every row below)

1. **The canvas is the stage.** Everything else is a lens on the canvas's selection (a person, a branch, the whole file), not another place to open a file and start again.
2. **One reader, one model, one file page, one settings place.** The reader is `/roots/js/worker.js` (the `Session`); the model is what it builds; the file page is "Your file"; the settings place is the Settings drawer. A second copy of any of them is a bug.
3. **Move the value, not the controls.** If R&R's control exists only because R&R had no canvas (a tab for the viewer, a second file picker, a header checkbox), it does not move. What it was *for* moves.
4. **`/roots/` stays live** (it was "unchanged" until 19 Nov 2026; since then it is Tree views only, see the top of this page) until each piece is better in the canvas, and then it links across rather than vanishing. Nothing in phases 0 to 2 changes how `/roots/` behaves; the only change under `/roots/js/` is that the import report's drawing code now lives in a shared module that `/roots/` itself also uses (its output was compared byte for byte with the live page).
5. **Archives are untouched until the last phase.** The eight archive sites vendor the tree-views template and the kit. No phase before the last edits either.
6. **Living people: every surface follows the canvas's living filter, and no surface weakens a default.** Today both pages show a file's living people as the file gives them until the visitor hides them, and both keep everything on the device. A new setting may only be *safer* than what exists, and a setting arriving from another device never replaces a choice made on this one.
7. **Nothing new leaves the device.** The only thing that reaches the server is what the six-word copy already carries, encrypted.

## What was found in the code (corrections to the first-pass sorting)

- The canvas **already has** its own "Fix list" tab (`tcFix`, the "!" marks), "Where next", "Research lines" (the archive's own drawing beside the tree), Compare with archives (the file beside one, several or all eight archives, in pairs; see below), the Path and Bloodline tools and a whole-tree look. These are not "to move": R&R's *Fix list* tab is a second, fuller version of one of them (rows grouped by what the reader has to do, with the Atlas's help). The work in phase 4 is to make the canvas's panel show that fuller list, not to port a tab.
- **The metrics strip is not shared code.** It is computed inside the tree-views template (`scripts/roots/tree-views.template.html`, `renderMetrics()`), so "move it" would have meant a second copy. Phase 1 writes it once as `site/public/roots/js/metrics.js` and a test runs the viewer's own code over the same trees and fails if they ever differ.
- **Export is GEDCOM-only.** A `tree.json` is not made again (the reader keeps no parsed GEDCOM for it) and an archive's tree is already published. "Your file" says so rather than offer a button that cannot work.
- **Orphans is already a top-level R&R tab** (the second shell in #65). Whether the canvas needs its own lens for it is a phase 3 question; Your file already shows the count.
- **The import report is two reports.** A GEDCOM gets the full four-section report; a `tree.json` has no place table or timings, so it gets its own short account. The shared renderer (`report-view.js`) takes a heading level so it sits under "Your file" without changing `/roots/`.
- R&R's saved-files list keeps **five** files in its own database (`roots-recent`); the canvas keeps **three** in `tcRecent`. They are different stores. Phase 1 makes the canvas one list instead of two (opening screen and file page draw the same list); merging with R&R's is left until R&R retires, because `/roots/` must not change.
- **Search is a tab, not a dock (19 Nov 2026).** The bottom search dock is gone: **Find** (a magnifying glass) is the first tab of the right-hand pane, with the box, one archives button (ticks, All, None), the recent people and the results, which can be clicked or dragged onto the canvas or into the relate slots. `/` opens it. While the canvas has no one on it, the same search is shown centred on the canvas and goes away when anyone is added. The bottom edge is the Trail band's; the dock now holds only the two relate slots while they are open. The pure parts are `find.js` in the Tree Canvas source (tested by `test/test-find.js` and `site/test/tree-canvas-find.test.js`).
- The "Keep your work" state from #63 is already the canvas's; it is shown, not rebuilt.
- **Compass replaces the Atlas map and Movements views (Nov 2026).** It is a page-level workspace over the canvas (`compass-view.js`, rules in `compass-model.js`), opened from the switcher: three round orange buttons, Canvas, Compass and Atlas, in the same place on both (`switcher.js`). It uses the loaded file and the Compare archive selection, so there is no second upload. Canvas and Compass are both kept alive: the canvas's iframe is only made inert under Compass and Compass's map is only hidden, so going between them redraws nothing (the year, selection, zoom, panel and the canvas's cards and view stay exactly as left). The Atlas is another page and opens in a new tab so the tree stays in memory; Alt-click leaves this page instead. The Tree Canvas source needs the same change as `scripts/roots/tree-canvas.template.html`: no Compass toolbar button, and a `tcAskCompass` message answered with `tcCompass` (the selected person).

## Phase plan

- **Phase 0 (this page).** Inventory, principles, decisions.
- **Phase 1: Your file.** One page over the canvas (menu "Your file", and the opening screen once a file is open): At a glance (the five counts), What was read (the import report), Keeping your work, Files and canvases on this device (one list), Export. Reuses the reader, the report renderer and the Keep state. Works for a file, a link, an archive and the invented example.
- **Phase 2: Settings.** One drawer: the living filter, links to MyHeritage and Ancestry, the Look, and remembering the last files. Persisted on this device; the choices that are not about family data travel in the six-word copy (opaque: three enumerated values, no names). The canvas's own duplicates of these controls go, inside the canvas page only.
  *As built (PR B):* the drawer is page-level, opened from the canvas menu, the opening screen and Your file. Living people is one switch with the reader's own rule explained (`/roots/`'s: no death recorded and born within 110 years, or no birth year); its default is unchanged (shown as the file gives them) and a chosen "hide" is remembered. The MyHeritage link and Ancestry site use the same `links` object as before and already travelled in the copy (`sites`). Look and "keep the last 3 files" were the canvas's own; the canvas's menu chips, Options box and tick are gone on the standalone page only (an archive's embedded canvas keeps them), leaving the eye button as the quick switch for the same living setting. Kept on this device as `ra-settings-v1` (written through to the canvas's older `loamTheme` and `tcRemember` keys, so earlier choices are honoured) and carried in the six-word copy as a `settings` section of three enumerated values; a value from another device only fills a choice this device has not made.
- **Phase 3: Tree lenses.** A frame in the canvas that shows a view for the current selection (hourglass, fan, atlas map, movements, eras, timeline, surnames). Views the canvas already does are retired after a side-by-side. `/roots/` keeps working.

A "Likely" chip (`roots/js/likely.js`, shared with the Choose-a-place section) marks the candidate where the people who use a text, and their relatives, are firmly recorded; it is a suggestion to copy, never a finding.
  - *R&R's Export tab was removed on 19 Nov 2026* (David: not needed anymore). The Cleaned export and place picking are not coming to the canvas (decision, 19 Nov 2026: not a tree-editing or storage site); Places to review moves to the Fix list as a cleanup checklist (copy the suggestion, open the person in your own tree, fix it there). R&R's Places panel said so until it was removed the same day, with the Fix list, Orphans, Import report and Tree canvas tabs.
  - *Built so far (a prototype, PR open):* the full Fix list workspace (checklist, filters, paging, "Open next 10 people", saved decisions, a priority order with a High / Medium / Low chip, an Order and a Rows sort), the per-person Fix tab, and aligned person rows (also on /roots/). ## Compare in pairs, and what it does to phase 3

Compare with archives (the visitor's file beside one archive, several, or all eight, paired person by person, one row to a generation) is a **lens that takes over the canvas's layout**, not one that only annotates the selection. Phase 3 had assumed the second kind. What building it showed the frame needs:

1. **A lens may own the arrangement.** The paired view draws its own cards in its own rows (the engine, `pairs.js`, hands `TC.arrange` one item per pair), so the Arrange button asks the lens first (`prArrange`), the status buttons and chips are an overlay layer (`#pairs`, hooked into `drawEdges` the way the generation bands and Lines mode are), and the usual cards, edges, pan, zoom, selection and minimap are reused unchanged. The hourglass and fan lenses need the same two hooks (a layer, and "who arranges") and can use `TC.arrange` the same way.
2. **A lens keeps its own choices, as opaque ids, in the per-tree record.** The paired view's choices (which archives, the starting people, accepted and rejected pairings) are one more field of the #63 record (`pr`), hashed like cards, strictly cleaned on the way into the six-word copy, capped at 400 pairings (about 12 KB at the cap, against a 150 KB per-tree limit and the server's 2 MB). The comparison canvas itself is never saved; the file's own arrangement stays as it was. A lens that needs state (a fan's root, a timeline's range) should add a field the same way, not a new store.
3. **A lens restores itself when the same tree is opened again,** and says so ("Your comparison came back") with a one-click way out.
4. **A lens's content is also a list.** The Compare tab lists every place as text (a person on each side, the state, the reason), so nothing depends on seeing the drawing.
5. **What it does not change:** nothing new leaves the device; the archives are read with the same plain, credential-less request as the single-archive compare, a few at a time, and a failure is named, never counted as "no one"; `/roots/` is untouched.

Effect on the plan: the "lens frame" dependency shrinks from a new component to those two hooks plus the per-tree field, which now exist, so the hourglass and fan lenses (M each) lose some of their cost; the order of phase 3 is unchanged. The paired view's counts (agree, to check, only in one) are a candidate for "At a glance" on Your file once a comparison has been run.

## Decisions needed from David

1. **Default for living people.** Today both pages start by showing living people as the file gives them (everything stays on the device). Phase 2 keeps that default and adds a remembered "hide" choice. Do you want the default changed to *hidden*? It is safer, and costs one click for people who want names.
2. **Does a setting follow you to another device?** Phase 2 carries the settings in the six-word copy but a device's own choice is never replaced by another device's (it only fills a setting that device has not made). The alternative, "latest change wins", is simpler to explain and can switch the living filter *off* from another device. Recommend: fill-empty only (as built).
3. **The eye button in the canvas toolbar.** It is the same living setting, kept as a quick switch because it is where people look. Say if you would rather it open Settings instead.
4. **R&R's five saved files versus the canvas's three.** Leave as they are until R&R retires, or merge at phase 4?
5. **Exporting a `tree.json`.** Not possible now. Do you want the canvas to be able to write one (so an archive's tree can be saved), as a phase 3 addition?
6. **Phase 3 order.** Which lenses first? Suggested: hourglass and fan (the most used), then the atlas map.

## How each phase is checked

Tests that run the viewer's own code (not a copy of its rules) wherever a number or rule is shared; a byte-for-byte comparison of anything `/roots/` still draws; the canvas opened in a new browser tab against the invented example family and the larger invented tree (never a real family file), at phone width, light and dark, with storage blocked, and by keyboard.
